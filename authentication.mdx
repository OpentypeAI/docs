Every `/v1` route takes a bearer credential in the `Authorization` header. Only `/healthz`, `/readyz`, and `/openapi.json` are public.

```bash
Authorization: Bearer otsk_...
```

Machines use **API keys**. The console uses a WorkOS session token in the same header; you do not need one to call the API.

## API keys

A key secret is `otsk_` followed by 64 hex characters. The `otsk_` prefix makes a leaked secret easy for secret scanners to spot.

- **Shown once.** The secret is in the body of `POST /v1/keys` (and of a rotation) and nowhere else. OpenType stores only its SHA-256 hash plus a display prefix like `otsk_a1b2c3d4`, so a lost secret cannot be recovered. Rotate the key instead.
- **Key id is not the secret.** A key has an id such as `key_...`, which you use in URLs. A secret sent where an id belongs is refused with `400 secret_in_path`.
- **Principal.** A key acts either as the user who created it (`{"type": "user", "id": ...}`) or as a service account (`{"type": "service_account", "id": ...}`). Creating a service-account key requires `members_write`. A key cannot act as a different user (`403 principal_is_not_the_caller`).

Create keys in the [console](https://console.opentype.dev/keys) or with the API:

<CodeGroup>

```bash cURL
curl -sS https://api.opentype.dev/v1/keys \
  -H "Authorization: Bearer $OPENTYPE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "ci-runner", "scopes": ["runs_write", "runs_read"]}'
```

```ts TypeScript
const res = await fetch("https://api.opentype.dev/v1/keys", {
  method: "POST",
  headers: { Authorization: `Bearer ${process.env.OPENTYPE_API_KEY}`, "Content-Type": "application/json" },
  body: JSON.stringify({ name: "ci-runner", scopes: ["runs_write", "runs_read"] }),
});
const key = await res.json();
// key.secret is only in this response. Store it in your secret manager now.
```

```python Python
import os, requests

res = requests.post(
    "https://api.opentype.dev/v1/keys",
    headers={"Authorization": f"Bearer {os.environ['OPENTYPE_API_KEY']}"},
    json={"name": "ci-runner", "scopes": ["runs_write", "runs_read"]},
)
key = res.json()
# key["secret"] is only in this response. Store it in your secret manager now.
```

</CodeGroup>

The response is `201` with the key metadata and `secret`.

## Scopes

A key carries a list of scopes, and each route requires one.

| Scope | Allows |
| --- | --- |
| `runs_write` | Create runs (`POST /v1/runs`). This scope can spend money. |
| `runs_read` | Read runs, list them, and stream them. |
| `keys_read` | List and read keys, without their secrets. |
| `keys_write` | Create, rotate, and revoke keys. |
| `members_read` | List organization members. |
| `members_write` | Invite members, change their roles, and remove them. Also required to create service-account keys. |
| `usage_read` | Read usage, the ledger, and quota. |
| `billing_read` | Read the credit balance. |
| `billing_write` | Change billing settings. |

**A key can never have more scopes than the account that creates it.** Requesting a scope you do not hold is `403 scope_exceeds_creator`, and an empty scope list is `400 empty_scopes`. Organization roles set the ceiling:

| Role | Scopes |
| --- | --- |
| `member` | `runs_read`, `keys_read`, `members_read` |
| `admin` | everything `member` has, plus `runs_write`, `keys_write`, `members_write` |
| `owner` | everything `admin` has, plus `billing_read`, `billing_write` |

A route called without its scope returns `403 scope_denied`, and the message names the missing scope.

## Rotation

`POST /v1/keys/{key_id}/rotate` issues a new secret for the same key id and returns it once.

<Warning>
The old secret stops working **immediately**. There is no overlap window. Deploy the new secret to every process that holds the key right after you rotate it.
</Warning>

A revoked key cannot be rotated (`409 key_revoked`).

## Revocation

`DELETE /v1/keys/{key_id}` revokes a key. It is idempotent: revoking a key that is already revoked returns `200` with the stored row, so a client that retries after a timeout gets confirmation that the key is dead. Revoked keys still appear in `GET /v1/keys`, with `state: "revoked"` and `revoked_at`.

Removing a member (`DELETE /v1/members/{member_id}`) revokes every key that acted as that member, in the same transaction.

## Errors

| Status | Code | Meaning |
| --- | --- | --- |
| `401` | `missing_credentials` | No `Authorization: Bearer` header. |
| `401` | `invalid_credential` | The credential was rejected. |
| `403` | `no_active_organization` | The credential names no organization. |
| `403` | `scope_denied` | The credential lacks the route's scope. |
| `503` | `auth_not_configured`, `trust_keys_unavailable` | OpenType cannot verify credentials right now. Retry with backoff; this is not your credential's fault. |

The full list is on [Errors](/errors).
